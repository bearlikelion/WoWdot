WrathGD

3.3.5a (12340) · AzerothCore · In development

The client runs: it logs in, makes a character and walks around Shadowglen. One wowdot build serves both clients, and one folder of GDScript too: a project setting picks the wire build, the packet parsers, the MPQ chain and the data tables.

Done so far

  • Login. SRP6 against the authserver, realm list, the RC4 header cipher and the WotLK auth session.
  • Characters. The character list, creating and deleting.
  • World. Entering the world on a WotLK map, with the player's update object read through the WotLK field indices.
  • Movement. Walk heartbeats land, the server keeps the position across a relog, and a GM teleport is acknowledged.
  • Large packets. The world socket takes the 5 byte header AzerothCore uses above 32 KB, which update objects need.
  • Chat. Lines go out and come back in the WotLK layout, whose message types are numbered differently.
  • Models. M2 version 264, whose geometry arrives from the .skin file beside the model.
  • Terrain. Azeroth and Northrend tiles, with MH2O water named out of LiquidType.dbc.
  • The screens. The login screen, the character list and the create screen, all shared with WoWGD, driving a real character into the world with nothing amiss in the log.

Next

  • The update fields and Spell columns the interface reads, which is what the HUD and tooltips want.
  • Animations, which version 264 moved into .anim files, hundreds per model.
  • The packets still parsed in the vanilla layout, and auras, which lost their update fields.
  • The 3.3.5a interface, whose FrameXML differs from 1.12's.

Too early to play, so there is nothing to download yet.

How it works

WoWdot is a C++ GDExtension that opens your MPQ archives, decodes the DBC tables, BLP textures, M2 and WMO models, ADT terrain, and speaks the game's network protocol.

It then exposes these to GDScript with Godot signals for gameplay, like the interface, world, and combat.

Your data, your install

WoWdot ships no Blizzard code, archives or extracted assets.

The clients read your MPQ archives and talk to whatever server you point them at.

Open source, but later

WoWdot will be MIT licensed.

The source is not published yet, so the builds come first while the client is still moving quickly. Every release zip carries the LICENSE and NOTICE.md the source will ship under.

About

Hi! I'm Mark and I make games.

I wanted to explore the possibilities of creating my own MMORPG, by diving deeper into the Godot game engine, and to understand how a game like World of Warcraft works under the hood.

This is an educational project, built for its own sake rather than as a product.
